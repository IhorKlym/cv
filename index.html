01

Робота з AI

Щодня працюю в Claude Code: це моє основне середовище розробки. Більшу частину коду пишуть агенти, а я виконую роль архітектора, рев’юера та інтегратора: формулюю задачу, розбиваю її на кроки, перевіряю результат і вирішую, що потрапляє в main.

  1. 01

    Оркестратор і субагенти

    Одна сесія планує роботу й перевіряє результат, окремі субагенти пишуть код і роблять незалежні рев’ю. Модель обираю під задачу: потужнішу для суттєвих змін, легшу для рутини.

  2. 02

    Репозиторій, готовий до агентів

    Harness engineering: конвенції в CLAUDE.md та AGENTS.md, постійна пам’ять проєкту з ухваленими рішеннями й типовими пастками, власні skills. Серед них фреймворк інженерної стратегії, аудит harness репозиторію і браузерна автоматизація, яка через Playwright MCP заповнює облік робочого часу.

  3. 03

    Специфікація як джерело істини

    Нумеровані вимоги визначають, що будувати. ID вимоги потрапляє в анотації коду й у тести, а автоматична перевірка показує, що покрито, а що ні. Правило просте: один крок, одна сесія, один pull request.

  4. 04

    Агенти за розкладом

    Щодня за розкладом запускається агент, який розбирає призначені мені GitHub issues. Прості задачі оформлює як pull request після справжнього локального прогону тестів, для складних пише аналіз. Сам він нічого не мерджить.

  5. 05

    Перевірка, а не довіра

    Тести й CI на GitHub Actions, наскрізні перевірки через Playwright і MCP, headless-прогони та реальні Safari і Chrome, скриншоти з реальних пристроїв. Кожен pull request переглядає та мерджить людина.

  6. 06

    LLM усередині продукту

    AI для мене не лише інструмент розробки. У Sumy Safety Bot повідомлення з кількох Telegram-каналів класифікує Claude Haiku: на виході структурований JSON, далі дедуплікація та одне зведене попередження в каналі.

Типовий цикл

  1. 1 Специфікація нумеровані вимоги з ID
  2. 2 План кроки розміром з один PR
  3. 3 Реалізація агентами субагенти, модель під задачу
  4. 4 Автоматична перевірка тести, CI, реальні браузери
  5. 5 Рев’ю і мердж людиною агент сам не мерджить

Що це дає. Повний продукт (API, бот, воркер, mini app, інфраструктура, документація) я доводжу до продакшену сам, хоча зазвичай для такого обсягу потрібна невелика команда.

  • ~50 запланованих задач / PR у TELEGA, весь продукт зроблено самостійно
  • 441 нумерована вимога в Догляну, кожна реалізована простежується до коду й тестів

Дослідження

PhD-дослідження [ додати: університет ] [ додати: роки ]

Інформаційна система підтримки прийняття рішень для ергономічного забезпечення надійності людино-машинної взаємодії в ERP-системах

Прототип ERGO-DSS адаптує метод оцінки надійності людини HEART. Умови, що провокують помилки (error-producing conditions), система вимірює автоматично з інтерфейсу, а не через експертні оцінки: розширення браузера збирає телеметрію, а обчислювальне ядро на Ruby рахує результат.

  1. Інтерфейсджерело вимірювань
  2. Розширення браузеразбирає телеметрію
  3. Ядро на Rubyрозрахунок за методом HEART
