01

Working with AI

I use Claude Code every day as my primary development environment. Agents write most of the code; I act as architect, reviewer and integrator: I frame the task, break it into steps, check the result and decide what makes it into main.

  1. 01

    Orchestrator and sub-agents

    One session plans the work and verifies the result; separate sub-agents write the code and run independent reviews. I pick the model per task: a heavier one for substantive changes, a lighter one for routine work.

  2. 02

    Agent-ready repositories

    Harness engineering: conventions in CLAUDE.md and AGENTS.md, persistent project memory of decisions made and known pitfalls, and custom skills. Among them: an engineering-strategy framework, a repository harness audit, and a browser-automation skill that fills in time tracking through Playwright MCP.

  3. 03

    The spec is the source of truth

    Numbered requirements define what gets built. Requirement IDs go into code annotations and tests, and an automated check shows what is covered and what is not. The rule is simple: one step, one session, one pull request.

  4. 04

    Scheduled agents

    Every day a scheduled agent goes through the GitHub issues assigned to me. Simple ones it ships as pull requests after a real local test run; for complex ones it writes an analysis. It never merges anything on its own.

  5. 05

    Verification over trust

    Tests and CI on GitHub Actions, end-to-end checks through Playwright and MCP, headless runs plus real Safari and Chrome, screenshots from real devices. Every pull request is reviewed and merged by a human.

  6. 06

    LLMs inside the product

    For me AI is not only a development tool. In Sumy Safety Bot, Claude Haiku classifies messages from several Telegram channels into structured JSON; the pipeline then de-duplicates them and posts one consolidated alert to a channel.

Typical loop

  1. 1 Spec numbered requirements with IDs
  2. 2 Plan steps the size of one PR
  3. 3 Agents implement sub-agents, model per task
  4. 4 Automated verification tests, CI, real browsers
  5. 5 Human review and merge agents never merge

What it adds up to. I take a complete product to production on my own (API, bot, worker, mini app, infrastructure, docs), a scope that would normally need a small team.

  • 441 numbered requirements in Dohlianu, each implemented one traced to code and tests
